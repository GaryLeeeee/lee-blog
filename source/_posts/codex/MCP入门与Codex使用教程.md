> MCP让Codex能够调用接入的工具、读取外部资料。日常使用的重点是接好工具、说清任务，并检查实际调用结果。
>
> - 本文以使用现成MCP服务为主，不从头开发服务。
> - 命令在终端执行，提示词在Codex对话中输入。
> - 示例中的仓库名、PR编号和页面链接需要替换为自己的内容。

## 一、MCP是什么？

MCP全称`Model Context Protocol`，可以理解成**AI连接工具的一套通用约定**。

比如，你想让Codex查看一条GitHub Issue（问题记录）的处理进度。接入GitHub MCP后，它可以读取状态和讨论，再向你解释，而不必等你手动复制页面内容。

```text
你：查看这条Issue处理到哪了
    ↓
Codex通过GitHub MCP调用查询工具
    ↓
工具读取GitHub上的状态和讨论
    ↓
Codex整理进展、负责人和待解决的问题
```

MCP本身不是一个模型，也不是安装后就拥有所有功能的软件。平时说的“装一个MCP”，通常是指**接入一个提供具体能力的MCP服务**。

这里的“服务”既可以是本机启动的程序，也可以是通过网址连接的远程服务。

## 二、可以接入哪些服务？

| 接入的服务或工具 | 常见用途 | 可以这样提问 |
| --- | --- | --- |
| GitHub | 查看Issue、PR改动和讨论 | “这次PR改了什么，哪些功能需要回归？” |
| Notion | 查找需求、会议纪要和项目文档 | “把这份需求整理成开发清单和测试点。” |
| REA | 分析已有Go程序或APK | “订单页的运费是本地计算，还是接口返回的？” |

GitHub和Notion都有官方MCP服务，需要接入并完成授权，能读到什么取决于账号权限。MCP不会绕过登录，也不会自动访问其他人的私有仓库或文档。

优先连接自己或团队已经使用的服务，不必为了MCP更换工具。已有命令行、源码搜索或内置工具能完成的任务，也可以继续使用它们。

## 三、两个常用例子

### 1、GitHub：了解PR改动和风险

接入GitHub MCP后，可以让Codex读取远端PR，不必逐条复制描述、代码差异和讨论。

```text
使用GitHub MCP读取<OWNER>/<REPO>的PR <PR_NUMBER>。
结合PR描述、代码改动和讨论，总结解决的问题、主要改动和潜在风险。
列出需要回归的功能，附对应文件位置或PR链接。
只读取，不发表评论、不合并PR、不修改代码。
```

也可以查询某个仓库里尚未解决的Issue，按已有标签和讨论整理问题清单。读取PR不等于已经运行测试，分析结果中应说明哪些风险还需要验证。

GitHub的Codex接入方式见文末官方指南；其中远程连接示例使用个人访问令牌（PAT）。查询场景应只授予目标仓库所需的读取权限，不要把令牌放进对话或仓库。

### 2、Notion：把需求整理成开发和测试清单

如果团队把需求和会议记录放在Notion，可以接入Notion MCP，减少来回复制文档的操作。

```text
使用Notion MCP读取这份需求：<NOTION_PAGE_URL>。
整理业务规则、需要开发的功能、测试点和待确认的问题。
每项注明来源页面；文档没写清楚的不要自行补成确定需求。
只读取，不修改Notion页面。
```

例如需求只写了“支付失败后允许重试”，可以让Codex指出缺少重试次数、重复扣款处理等约定，再交给产品确认，而不是直接猜规则写代码。

如果是分析本地Go程序或APK，可以使用REA，接入步骤和案例见{% post_link codex/REA使用教程 REA使用教程 %}。

## 四、在Codex中怎么接入？

### 1、本地和远程，接法不同

| 连接方式 | 配置什么 | 常见场景 |
| --- | --- | --- |
| 本地程序，即`STDIO` | 启动命令和参数 | REA等在本机处理文件的工具 |
| 远程连接，即`Streamable HTTP` | 服务提供的网址 | GitHub、Notion等三方服务 |

本地服务通常由Codex按配置启动，不需要手工给每个工具一直开着终端。远程服务则需要网络可达，并完成它要求的登录或授权。

**普通网站地址不一定是MCP地址。** 应使用服务方提供的端点，不要自行在网址后面加`/mcp`就认为能用。

### 2、以Notion为例：添加并授权

已安装Codex CLI时，在终端执行：

```bash
codex mcp add notion --url https://mcp.notion.com/mcp
codex mcp login notion
codex mcp list
```

按浏览器提示登录Notion并确认授权范围。授权后，MCP可以访问你在所选工作区内有权限的内容，服务也提供写入能力；本文案例只做查询，不代表连接本身就是只读的。

添加后重启对应客户端或连接。CLI对话中可输入`/mcp`查看当前工具，再用上面的需求整理提示词做一次实际查询。`codex mcp list`有记录只说明配置存在，应以工具成功返回内容为准；以后使用不必重复添加。

### 3、配置存在哪里？

Codex通常使用个人配置`~/.codex/config.toml`；只想给某个项目使用时，可以配置项目内的`.codex/config.toml`，项目配置需要受到信任才会加载。

例如，手动添加Notion连接可写成下面这样，与前面的`codex mcp add`二选一；手动添加后仍需登录授权：

```toml
[mcp_servers.notion]
url = "https://mcp.notion.com/mcp"
```

不要覆盖整个配置文件；已有同名条目时修改原条目。同一台主机、同一套Codex配置下，客户端可以共享连接；换电脑或改用远程环境后，需要检查那里的配置和文件路径。

### 4、不再使用时移除

不再使用某条手动添加的连接时：

```bash
codex mcp remove <服务名>
```

移除连接不等于卸载本地服务程序。

## 五、常见问题与使用建议

| 现象 | 先检查什么 |
| --- | --- |
| 配置了，但任务里没有工具 | 连接是否启用、是否重启，以及当前任务是否运行在同一台主机 |
| 本地服务启动失败 | 启动命令、依赖和文件路径是否在Codex所在环境可用 |
| 远程服务连不上 | MCP网址、网络和登录状态 |
| Codex没有使用指定工具 | 明确写“使用某某服务查询什么”，并检查调用记录 |
| 工具能调用，但查不到数据 | 账号权限、查询条件和工具实际支持范围 |

- **把问题说具体**：写清服务名、目标和希望得到的结果，例如“读取这个PR并列出回归点”，而不只是“用一下MCP”。
- **说明操作范围**：查询、修改、发送消息是不同操作；涉及修改时，把允许改什么写清楚。
- **凭据交给配置和授权流程**：不要把真实Token、数据库密码或含凭据的连接串粘到对话和文章里；按服务文档使用登录授权或环境变量。
- **本地运行不等于结果只留在本地**：工具结果会进入助手上下文，继续按团队的数据使用要求处理。
- **只接入当前需要的服务**：工具返回的内容也需要核对，尤其不能把外部文档中的指令当成你的新要求。
